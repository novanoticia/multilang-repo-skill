# 语言选择、规范化与回退（D2–D7）

在阶段 2 阅读本文件，以推荐选择策略；在阶段 3 阅读本文件，以设计该策略。如果生态系统已经解决了这个问题
（i18next 的协商、Android 或 Apple 的资源、Web 框架的 `Accept-Language`……），使用其机制，只应用本文件中
尚缺的部分：用例表和测试。

## D2 来源顺序

显式（请求本身中的标记或设置）> 配置（项目或用户的配置）>
环境（环境变量、系统语言、`Accept-Language`、用例的语言）> 默认。

只有在用户于阶段 2 接受时，环境才会参与。用户撰写自己请求时所用的语言同样属于环境（绝不是粘贴文本的语言）：
如果用户选择，可以使用它，作为已批准的更改。检测它会使当前收到默认语言的人改为收到另一种语言：这是 D1
要求批准的行为变更，而不是细枝末节。按项目类型推荐：
- 智能体和指令：默认只认显式标记；粘贴文本的语言绝不起决定作用，请求本身的语言仅在用户选择时才起作用
  （见上一段）。
- 具有平台惯例的程序（移动或桌面应用、带语言协商的 Web）：采用生态系统的惯例，作为待批准的更改提出。

## D3 规范化与回退链

在查找目录之前，先规范化为规范的 BCP 47 标签：
- 不区分大小写：`EN-us` → `en-US`。
- `_` → `-`。去掉字符集（`fr_FR.UTF-8`）。POSIX 修饰符若表示文字或变体则予以转换
  （`sr_RS@latin` → `sr-Latn-RS`，`ca_ES@valencia` → `ca-ES-valencia`），否则去掉（`@euro`）。
- `C` 和 `POSIX` 表示“无偏好”，而不是未知语言。它们在 CI 和容器中很常见。
- **保留文字子标签。** `zh-Hant` 不是 `zh-Hans`，`sr-Latn` 也不是 `sr-Cyrl`。
  截断到第一个组成部分，会把简体中文提供给要求繁体的人。
- 已淘汰的代码：`iw` → `he`，`in` → `id`，`ji` → `yi`。

回退链，每个环节都要声明并测试：
1. 所请求的标签。
2. 逐级截断（RFC 4647，“lookup”）：`zh-Hant-TW` → `zh-Hant` → `zh`。
3. 在截断失效之处使用显式环节：`zh-TW` → `zh-Hant`；`es-AR` → `es-419`
   （截断只会得到 `es`；父级 `es-419` 来自生态系统的 CLDR 数据或项目的声明，不能推断）。
4. 默认语言。

如果生态系统自带解析机制（`fallbackLng`、按限定符查找资源、父级的 CLDR 数据），检查并记录它，而不是重新实现。

## D4 无法提供的输入

区分值的来源：
- **显式**的值未知、为空或格式错误：给出可见的警告并附可用列表，使用去掉该输入后会得到的语言
  （D2 中下一个有效来源；若没有，则用默认）。在智能体中，继续使用下一个来源。在程序中，依照项目惯例决定并记录：
  带退出码的用法错误（无效参数），或警告后继续。
- **环境**中无目录（`LANG=de_DE.UTF-8` 但没有德语）：回退而不报错，至多写一条调试日志。报错会使程序对所有使用该系统的用户崩溃。
- 空的环境变量 = 不存在。
- 面对无效输入（非 UTF-8 文本、损坏的 JSON），绝不静默降级：返回明确的警告。
- “不新增警告”指无标记的输出（D1）。对无效的显式标记或选项发出的警告予以保留，除非用户明确将其排除，且知道此后会在不加解释的情况下落到下一个来源（D2）。

## D5 智能体中的带键标记

在智能体中，`en`、`es` 或 `a` 都是真实的词。要求使用带键标记（`idioma=en`、
`lang=fr`），并且只在用户自己的消息中识别，绝不在第三方数据（粘贴的邮件或文件）中识别。稳妥的实现：
只在第一个非空行中查找，这样粘贴文本内的标记不会被计入。选择不会出现在常见内容中的键：如果人们会粘贴 HTML
或代码，`lang` 会产生误报（`lang="en"`）；只使用 `idioma` 或自定义的键（脚本中的 `--claves`）。同时决定持久性并加以记录：
例如，每次调用各自决定语言，只有不带命令的后续消息保留之前的语言。

## D6 一条规则，一张用例表

只写一条选择规则，并测试每个用例：

| 用例 | 示例 | 预期 |
|---|---|---|
| 有效标记 | `idioma=en` | `en`，来源为标记 |
| 未知 | `idioma=de`，但没有德语 | 可见警告；下一个来源 |
| 为空 | `idioma=` | 可见警告；下一个来源 |
| 格式错误 | `idioma=e1` | 可见警告；下一个来源 |
| 重复 | `idioma=fr lang=en` | 第一个生效；警告 |
| 大小写 | `IDIOMA=EN` | `en` |
| POSIX 区域设置 | `idioma=fr_FR.UTF-8` | `fr`（回退 `fr-FR` → `fr`） |
| POSIX 修饰符 | `sr_RS@latin`，且有 `sr-Latn` | `sr-Latn`（链 `sr-Latn-RS` → `sr-Latn`） |
| 第一行中的代码 | `lang="en"` 或 `<html lang="en">`，键为 `lang` | 视为标记（`en`，或格式错误标记的警告）：在会粘贴代码的场景中，不要把 `lang` 用作键（D5） |
| 粘贴时带标点或引号 | `(idioma=en),`、`idioma="en"`、`«idioma=fr»` | 可识别 |
| 孤立的代码 | “报告中的 en 一词……” | 不是标记 |
| 与默认相同 | `idioma=es` | `es`，来源为标记 |
| 位于另一个词内部 | `subidioma=en` | 不是标记 |
| 在他人的数据中 | 标记位于以“>”引用的文本中，或位于第一行之后 | 不计入（限制：如果粘贴的文本占据不带“>”的第一行，则计入） |
| 文字 | `zh-Hant-TW` | `zh-Hant` |
| 区域回退 | `pt-BR`，但没有 `pt-BR` | `pt` |
| 已淘汰的代码 | `iw` | `he` |
| 技术性环境 | `LANG=C.UTF-8` | 无偏好，无警告 |
| 环境中无目录 | `LANG=de_DE.UTF-8` | 默认，警告不可见 |
| 非 UTF-8 输入 | 无效字节 | 警告 `entrada_invalida` |

“重复”一行针对消息中的标记。在命令行选项中，重复遵循解析器的惯例（argparse 中最后一个生效）：请予以声明。

添加一项完备性测试：使用固定种子的随机输入，没有任何一个会使解析失败。

## D7 [híbrido] 规则存在于代码中

如果模型调用脚本，选择规则就存在于脚本中，而不是只存在于文字里：
- 消息**通过标准输入从临时文件**原样传入，该文件由智能体用其文件写入工具写出，不经过 shell，且位于仓库之外。
  绝不作为参数，也不放进手写的 JSON：撇号（“j'aimerais”）、引号或 `$(…)` 会破坏或改变命令。也不要用固定分隔符的 heredoc：
  如果消息（或其中粘贴的文本）含有一行与分隔符相同，heredoc 会提前结束，其后的内容会被当作命令执行。
- 全函数：任何输入都不会使其失败。返回 JSON，含语言、来源、链、警告和可用列表。警告带有代码：向用户展示你的目录中对应该代码的文本；详情字段仅用于诊断。
- 如果输入无效，返回明确的警告，供智能体展示。
- 按你所记录的**原样测试该命令**，用撇号、引号、`$(…)`、反引号、与分隔符相同的一行、重音符号、换行和含空格的路径来执行，并用无害的金丝雀（临时文件的 `touch`）检查没有任何内容被执行。

经过测试的参考实现：[scripts/resolver_idioma.py](../../../scripts/resolver_idioma.py)。
可用它对照真实目录来测试用例表；仅当已批准的设计有此安排时才把它复制到项目中，并调整标记的键和回退环节。

```bash
# 智能体事先用其文件工具把消息写入 /ruta/temporal/mensaje.txt。
python3 <skill>/scripts/resolver_idioma.py --catalogos ruta/a/catalogos --defecto es \
  --respaldo zh-TW=zh-Hant < /ruta/temporal/mensaje.txt
```
