# 文档、版本与包（Doc1–Doc9）

在阶段 7 阅读，配合 [documentación] 或 [paquete]。遵循仓库的惯例（R17）：
如果它不使用 CHANGELOG、`AGENTS.md` 或待办记录，先提议创建，再动手创建。

**Doc1 README。** 如何选择语言、翻译什么和不翻译什么（机器契约、模型自由文本）、如何添加语言、边界情况、限制（检测器未覆盖的内容、实验性语言），以及翻译的真实状态（`borrador-ia`（AI 草稿）、`revisado`……），每种语言一次。AI 参与撰写的说明遵循 R16。如果范围较小，
一个多语言章节就够了；除非被要求，不要翻译整个 README。翻译文档时，代码块、命令、
锚点和链接保持原样。

**Doc2 手动安装途径。** 如果其中某种需要手动复制文件，就把新增的文件
（目录、脚本）加入其清单。没有它们，这项功能对以此方式安装的人来说就不存在。

**Doc3 `AGENTS.md` 或 `CLAUDE.md`。** 如果存在：不在目录之外写新的字面文本；
分隔块；frontmatter 保持不变；不可触碰的文件；对高风险差异进行人工审阅；验证命令；CI 为红色时不合并；下一次
版本变更时该做什么；以及已知的他人待办事项。如果只存在其中之一，检查它是否链接到另一个。

**Doc4 版本。** 依照项目的策略（例如 semver：兼容的功能是 minor），若有脚本就使用其脚本，
同时更新所有清单，并用一项测试对它们进行比较（P11）。

**Doc5 CHANGELOG。** 新增、更改、修复和限制，包括已批准的例外
（D23）以及原文中有更改的行。收尾之前，查找所引用的每个数字（键、
破坏、场景、大小），并与当前状态比较（R9）。

**Doc6 待办记录**（`PENDIENTES.md` 或仓库中的等效文件）。仅记录
已核实的内容：什么需要有人参与（审阅、凭据），什么需要另一个会话或对
域名的访问，缺少哪些来源，哪些场景尚未执行，以及哪些更改尚未进入主分支。

**Doc7 [paquete] 包的内容。** 打包脚本包含所有新文件且仅包含这些，
并用 P9 证明。如果已有下载的旧包，版本说明要写明
须重新安装完整的包。

**Doc8 [paquete] 附件的名称。** 如果 README 按名称链接某个附件（例如
`releases/latest/download/<nombre>.zip`），附件就必须恰好叫这个名字：带版本后缀会
破坏该链接。

**Doc9 使用手册，如果存在。** 修改之前通读全文。保留其结构和
编号，因为其他部分会引用它们；把新内容加在末尾，并在开头放一个新内容提示框。如果生成 PDF（例如用无界面浏览器从 HTML 生成），
目视检查封面和一页带表格的页面。附上 AI 说明（R16），并把
旧版本保留为历史。
