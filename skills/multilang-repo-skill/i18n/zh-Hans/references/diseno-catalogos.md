# 目录、键与执行（D8–D15、D17–D20）

在涉及 [ecosistema]、[programa]，或项目将拥有自己的目录时阅读本文。

## 内容
- 首先，看生态
- D8–D13 目录与键
- D14–D15 执行与插值
- D17–D20 数据、产物与依赖语言的逻辑

## 首先，看生态

如果项目已有国际化，或其生态有标准（gettext、i18next、ICU MessageFormat，若项目已在使用则包括 MessageFormat 2，以及 Fluent、Rails I18n、`strings.xml`、String Catalogs、ARB 等），就使用它的格式、提取器、复数规则、回退和验证器。此时 D8–D9 不再适用，你的工作是覆盖率、术语表、测试和审查。只有当格式是自有 JSON 或 i18next 的 JSON，且项目没有验证器时（P6），`validar_catalogos.py` 才有用；它不解析 ICU 或 ARB。把下面的内容迁移到该格式的原生机制：gettext 中用 `msgctxt` 和给翻译者的注释，ARB 中用带 `description` 的 `@clave`，XLIFF 中用注记，Android 中用 `translatable="false"`。不要强加该格式不支持的字段或编码。

若尚未实现国际化，生态就是语言或框架的标准机制。先核查在不安装任何东西的前提下它能覆盖什么：Python 的 `gettext` 模块只能读取已编译的 `.mo`；提取和编译需要 `xgettext` 和 `msgfmt`（GNU gettext）或 Babel。若缺少这些工具，安装就是一项决定（R2）：把它与自有目录（D8）作为备选方案一并提出。只有当项目没有构建步骤时，才把 `.mo` 纳入版本管理，并配一项测试，按内容而不是按字节把它们与对应的 `.po` 比较（例如用 `gettext.GNUTranslations` 加载后比较）：不同编译器会产生不同字节。若缺少该工具，测试跳过并如实声明。

## 目录与键

**D8 自有目录（仅在没有生态时）。** 每种语言一个文件，添加时自动发现：代码不枚举语言，辅助文件（术语表、模式）不算作语言。通过 `t(clave, **datos)` 访问；在指令中则使用“键 → 语句”目录，由模型逐字复制。
- 若缺少某个键，回退到默认语言并记录（在测试中则失败）。若默认语言中也缺少，则是编程错误。
- 按键回退会让输出混杂多种语言。只有当验证器判定某种语言完整时，才将其作为完整语言发布。不完整的语言可以留在仓库中，标记为 `experimental`（实验性）（D12），并声明其限制；验证器将其报告为部分覆盖，而不是错误。

**D9 默认语言是参照。** 其语句就是原文的字面量：用工具提取（P3），不要手工改写。它可以带有新键（原文没有的警告），标记为 `origen: nuevo`。

**D10 一个字面量，一个键。** 每条完整的语句一个键，标题、标签、停止提问以及每个选项列表（作为一个整体）也是如此。不要用翻译后的片段拼接语句。
- 复数：使用该语言的 CLDR 类别（`zero`、`one`、`two`、`few`、`many`、`other`；每种语言只用其中一个子集），并采用生态的机制：ICU 复数、i18next 后缀、带 `Plural-Forms` 的 `ngettext`、`<plurals>`。只有当所有受支持的语言以及所显示的数字都只用这两个类别时，两个键（`uno`/`otros`）才够用。否则，声明该限制。
- [instrucciones] 区分“目录字面量：原样复制”与“方括号内的指令：由你自行撰写”。方括号内的选项列表不是指令。对填写方括号空位，只确定一种策略。

**D11 按比例为每个键添加元数据。** 在自有目录中：`origen`（`original` | `nuevo`）、`fuente`（原文的文件和行号，不计入新增的块）、`contexto`（给翻译者或审阅者的一行说明：出现位置、含义、长度限制）、`riesgo`（`alto`（高），用于确认不可逆操作、限制或安全的语句）、`invariable`（由文本本身证明合理：符号、代码或专有名称）和 `maquina`（在所有语言中相同）。在 S 规模下，只在需要处给出 `contexto` 和 `riesgo` 即可。在生态格式中，使用其原生机制。自有 JSON 中的形式：元数据放在参照中，写成 `"@clave": {"contexto": …, "riesgo": …, "invariable": true}`（ARB 风格），验证器在对等性检查中会排除它。在所有语言中都不变的内容在此处声明；仅在某一种语言中相同的内容（在相近语言之间很常见）则在该目录的 `_meta.invariables` 中连同理由一起声明。

**D12 每种语言的状态。** `referencia`、`borrador-ia`（AI 草稿）、`experimental` 或 `revisado`，并注明由谁撰写、由谁审阅。`experimental` 是不完整的，或属于无法评判的语言的 `borrador-ia`：除了未经审阅之外，还带有加强警告（T6）。`revisado` 要求有明确身份的审阅者；另一个模型的意见不会改变状态。有了人工审阅后，更新该字段即可。记录位置：在自有 JSON 目录中，记在 `_meta`；在不支持该字段的生态格式中（例如应用原样加载的 i18next JSON），记在项目文档中（README 的语言部分）或单独的状态文件中，绝不添加加载器会显示或拒绝的字段。[scripts/validar_catalogos.py](../../../scripts/validar_catalogos.py) 在 JSON 目录中检查这种一致性（`_meta.estado`、`_meta.revisado_por`）。

**D13 文件形式。** 首先遵循生态格式的要求：有些格式在头部声明编码，有些遗留格式不是 UTF-8，所以要核实而不要假设。没有强制格式时：不带 BOM 的 UTF-8、末尾换行、确定的键顺序，以及新翻译采用 Unicode NFC。如果规范化会改变默认输出的字节（D1），就不要规范化参照字面量；把它声明为限制，或申请例外。

## 执行与插值

**D14 运行时的语言状态。** 在单请求进程中，启动时设定的全局语言即可。在服务器、并发任务或库中，语言按请求或按上下文传递，绝不放在共享的全局变量中。

**D15 模板与插值。** 只用具名字段。字面花括号要转义，被插值的数据绝不再被当作模板、标记或指令重新解释。在给模型的指令中，把被插值的数据界定为数据（S1）。

## 数据、产物与依赖语言的逻辑

**D17 配置数据中的文本。** 原文语言保持原位，其他语言按键覆盖：每种文本和每种语言只有唯一来源。如果原本有一个被忽略的语言字段现在被读取，这就是一项变更，要写入 CHANGELOG。

**D18 产物（E）。** 与用户一起决定所选语言是否影响它们。确保它们不混用语言，并在支持的格式中声明语言（HTML 中的 `lang`，PDF 中的元数据）。给默认输出添加该属性会改变其字节，所以这是需要批准的例外（D23）。

**D19 所建议的内容必须能被识别。** 如果程序以某种语言建议一句话，它的检测器就必须能以该语言识别这句话。触发某种模式的语句（“执行”“撤销”）同样是目录字面量。以散文形式显示、又作为输入返回的值，按与目录等价的方式识别。

**D20 `--help` 与解析器错误。** 它们通常在知道语言之前就已构建：在构建解析器之前先确定语言，从而翻译它们，或声明该限制。辅助脚本的消息可以保留原文语言，只要加以声明。新增选项（`--idioma`）本身就会改变默认语言下的帮助和用法行。如果用户要求了该选项，这一变更就属于所要求的内容：写入变更清单（D1），在摘要中说明，其余部分逐字节比较。如果用户没有要求（按标记或变量选择），则未经批准不要显示它：在帮助中隐藏它（例如 `help=argparse.SUPPRESS`），并另行记录。无论是否隐藏，新选项都会改变 argparse 接受的缩写（若已存在 `--input`，则 `--i` 变得有歧义）：选一个与现有选项没有共同前缀的名称，或者把目前可用的缩写纳入基线（P2）。
